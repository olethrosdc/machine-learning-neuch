* The algorithm
** $k$ Nearest Neighbours

*** The Nearest Neighbour algorithm
**** Pseudocode
#+ATTR_BEAMER: :overlay <+->
- Input: Data $(x_t, y_t)_{t=1}^T$, test point $x$, distance $d$ 
- $t^* = \argmin_t d(x_t, x)$ /// How do we implement this?
- Return $\hat{y}_t = y_{t^*}$

#+BEAMER: \pause
**** Classification
     $\hat{y}_t  \in [m] \equiv \{1, \ldots, m\}$
     
#+BEAMER: \pause
**** Regression
$\hat{y}_t  \in \Reals^m$

*** The k-Nearest Neighbour algorithm

**** Pseudocode
#+ATTR_BEAMER: :overlay <+->
- Input: Data $(x_t, y_t)_{t=1}^T$, test point $x$, distance $d$, neighbours \(k\)
- Calculate $h_t = d(x_t, x)$ for all $t$.
- Get sorted indices $s = \texttt{argsort}(h)$ so that $d(x_{s_i}, x) \leq d(x_{s_{i+1}}, x)$ for all $i$. 
- Return $\sum_{i=1}^k y_{s_i} / k$.

#+BEAMER: \pause
**** Classification
- We use a *one-hot encoding* $(0, \ldots, 0, 1, 0, \ldots, 0)$, with $y_t \in \{0,1\}^m$.
- The class of the \(t\)-th example is $j$ $\Leftrightarrow$ $y_{t,j} = 1$.
- Equivalently, return $p$ with 
\[
p_i = \sum_{t=1}^k \ind{y_{s_t} = i} / k
\]
#+BEAMER: \pause
**** Regression
- $y_t  \in \Reals^m$, so we need do nothing

*** Distance function
**** For data in $\Reals^n$, \(p\)-norm
\[
d(x,y) = \|x - y\|_p
\]
**** Scaled norms
When features having varying scales:
\[
d(x,y) = \|S x - S y\|_p
\]
Or pre-scale the data

**** Complex data
- Manifold distances
- Graph distance

*** Distances 
**** A distance $d(\cdot, \cdot)$:
- Identity $d(x,x) = 0$.
- Positivity $d(x,y) > 0$ if $x \neq y$.
- Symmetry $d(y,x) = d(x,y)$.
- Triangle inequality $d(x,y) \leq d(x,z) + d(z,y)$.
**** For data in $\Reals^n$, $p$-norm
\[
d(x,y) = \|x - y\|_p
\]
*** Norms;
**** A norm $\|\cdot\|$
- Zero element $\|0\| = 0$.
- Homogeneity $\|cx\| = c \|x\|$ for any scalar $a$.
- Triangle inequality $\|x + y\| \leq \|x\| + \|y\|$.
**** \(p\)-norm
\[
\|z\|_p = \left(\sum_i z_i^p\right)^{1/p}
\]
*** Neighbourhood calculation
If we have $T$ datapoints
**** Sort and top $K$.
- Requires $O(T \ln T)$ time
**** Use the Cover-Tree or KD-Tree algorithm
- Requires $O(c K \ln T)$ time.
- $c$ depends on the data distribution.


*** Making a decision
**** kNN as a *model*
- Given features $x$, we get a vector $p$ of class probabilities:
\[
p_i = P(y = i | x),
\]
where $P(y = i | x)$ is the probability that  $y$ is $i$, given $x$.
#+BEAMER: \pause
**** Decisions to maximise accuracy
At time $t$:
#+ATTR_BEAMER: :overlay <+->
- We observe features $x_t$
- We *predict* label $a_t = \argmax_i P(y_t = i | x_t)$
- We observe the actual label $y_t$.
- We *win* if $y_t = a_t$ and *lose* otherwise
#+BEAMER: \pause
**** The model versus the prediction
- The *model* $P$ tells us the probability of different classes.
- When we *decide* what our prediction should be, we can *use* the model.
- We will use $\pi$ to denote the *decision rule* or *policy*.
*** Decisions versus predictions
- We frequently need to make a *decision*, instead of just a *prediction*.
- Our *utility* function $U(y, a)$ represents our *preferences*.
- The space of *actions* $A$ is /not identical/ to the set of *labels* $Y$.

**** Classification decision to maximise expected utility
- Expected utility of a single decision
\[
\E[U | a, x] = \sum_y P(y | x, a) U(y, a) = \sum_y P(y | x) U(y, a)
\]
- The decision maximising expected utility
\[
a^* = \argmax_a \E[U | a, x] 
\]

**** Level notes
- *BSc*: Focus on the shape of the curve you just plotted. In plain language, what does it tell you about "knowing too little" versus "knowing too much" from the data? You'll see this exact shape of curve again and again this semester: start building intuition for it now.
- *MSc*: kNN regression is quietly estimating something specific: $\hat y(x) = \frac{1}{k}\sum_{i \in N_k(x)} y_i$ is an estimator of the *conditional expectation* $\E[Y \mid X = x]$. Write down why averaging nearby $y$-values is a sensible way to estimate $\E[Y\mid X=x]$, and what happens to this estimator as $k \to \infty$ with $k/T \to 0$. (If conditional expectation feels shaky, this is the moment to fix that: it underlies almost everything from here on, and it's worth re-deriving rather than assuming.)
** Activity 2: Deciding, not just predicting :activity:
*** Setup
As a class, agree on a utility matrix $U(y,a)$ for the spam example from the slides, by filling in the table:
|----------+------+------+-------|
| Utility  | Pass | Flag | Trash |

*** Tasks
- Fit a kNN classifier and call =predict_proba()= to get $P(y \mid x)$ for each test point.
- Write a function /utilityScore(y, actions, U)/ that takes the true labels $y_t$ and chosen actions $a_t$, and returns $\sum_{t=1}^T U(y_t, a_t) / T$.
- Write a second function /utilityAction(probs, U)/ that returns, for each test point, the action $a^*$ maximising expected utility under $P(y\mid x)$ and your $U$.
- Compare the average utility of plain =predict()= (most likely class) against your =utilityAction()=. Which one wins? Does the answer depend on which $U$ you chose?
**** Level notes
- *BSc*: The hard part of this exercise isn't the code — it's agreeing on the utility table. Notice how a vague goal ("stop spam") had to become numbers before anything could be computed. That translation step, turning a question into something measurable, is the scientific-method skill this course is built around.
- *MSc*: Once you have $a^* = \argmax_a \sum_y P(y|x) U(y,a)$, argue that no other decision rule can achieve higher expected utility under your model. Then ask: what changes once $P(y|x)$ is *estimated* (e.g. via kNN) rather than known exactly? Which new source of error are you now exposed to that wasn't there before?

*** Deciding from a generic utility
Let $U(y, a)$ be an arbitrary utility matrix and $P(y \mid x)$ an arbitrary model.
- Write down the expected utility of action $a$, and the action $a^*$ that maximises it.
- Show that if $U(y, a) = \ind{y = a}$ — you only care about being exactly right — then $a^*$ is the most likely class, $\argmax_y P(y \mid x)$.
- Now construct your *own* utility matrix $U$ over 3 classes and 3 actions, for which $a^*$ is *not* the most likely class for some $P(y\mid x)$ you choose. In words, explain why your $U$ creates this mismatch — and compare it to the utility table your class agreed on in Activity 2.
**** Level notes
- *BSc*: Constructing your own mismatched $U$ and explaining *why* it creates a mismatch, in plain words, is the actual goal: not the algebra.
- *MSc*: Make sure your proof for the $U(y,a)=\ind{y=a}$ case is a genuine proof, not "it's obvious": show the sum collapses to a single term per candidate $a$, and argue why that term is maximised exactly at the most likely class.
